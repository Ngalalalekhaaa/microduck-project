# 2026-10-28 六模型：仿真录像与 Xbox 部署

新增空闲十字键控制入口见 [Xbox 四模型按键部署](Xbox四模型按键部署.md)，四模型更新包名为 `microduck-xbox-four-actions-20261028.tar.gz`。本页保留此前按启动参数选择模型的方法。

六份权重已完成 **55 个短回合、627 秒** CPU MuJoCo + HD-1910 BAM 仿真，保存 **21 段 MP4**。本次未连接、驱动真机。下面的安装包用于更新**已经完成机械/HOME/IMU 标定**的 Radxa；从空机器开始，先按项目根目录 `README-从零复现.md` 第 0–14 节操作。

## 1. 测试结论

| 模型 | 本次测试 | 结论 |
| --- | --- | --- |
| 坐站 1699 | 基线、摩擦 ×0.8/1.2、重心 X ±15 mm，共 5 回合 | 基线正常；+15 mm 时未坐下，4 个条件通过筛查 |
| 摩擦坐站 2598 | 同上 | +15 mm 时站起前倾约 31.4°，4 个条件通过 |
| 重心坐站 2598 | 同上 | 5 个条件均通过，作为本次坐站首选 |
| 行走 1849 | 9 种指令 ×3 组初始/扰动条件，每回合 12 秒 | 无摔倒；0.2/0.3 m/s 前进实测约 0.187/0.253 m/s；低速、后退、侧移、原地转向几乎无响应 |
| 前滚翻 1600 | 3 种固定切换时序 ×3 初始条件；另 3 次部署监测联调 | 12 次均翻转后站稳；部署监测在开始翻滚后约 1.4 秒切回站立 |
| 俯身啄取 2249 | 连续 3 个 4 秒周期 | 均恢复站立；嘴最低约 17 mm，头部未触地 |

条件通过数只描述这些短回合，不能当作真机成功率。发送方完整训练配置未提供；采用本地机器人几何、BAM 摩擦、电池/延迟参数。坐站的重心偏移作用于躯干及头颈刚体；行走两组扰动同时改变摩擦、重心、延迟和初态。未覆盖完整训练随机化、背隙、真实 IMU 冲击误差与串口时序。

**默认保留已有行走模型**，不会用 1849 替换已验证的行走。要试 1849，请显式选择 `--walking new`。前滚翻有头部接触地面，默认为关闭，需显式 `--roulade on`；在软垫、开阔地进行首次实机验证。

原 Xbox 包装器使用 `--log-only-target-angles`：策略目标角限、目标跳变超限仅记录，保留原始策略动作；实际关节角、反馈连续性、编码器单圈范围、IMU/循环时效、电压和温度检查仍生效。本次前滚翻目标单步跳变约 57–65°，**没有通过默认 0.6 rad 的严格目标跳变门限**；不能把仿真成功理解为全部硬件保护均已验收。新代码没有另行关闭反馈保护，也没有裁剪滚翻动作来掩盖这个问题。

录像为 H.264、1280×720、25 fps，保留双视角、时间和动作信息。推荐先看 `postures/sitstand_com_2598__baseline.mp4`、`roulade/monitor_seed0.mp4`、`walk/walk1849_forward_020_seed0.mp4`。目录中 `SHA256SUMS` 可检查录像是否损坏：

```bash
cd ~/microduck/videos/20261028_model_suite
```

备份时同时复制视频包及其 `.sha256`；报告目录需另行备份。重新仿真会写同名结果，需要保留旧回合时先复制旧目录。三个测试入口：

```bash
cd ~/microduck
```

## 3. 连接真机后安装

电脑端，输入实际 IP；`wmh` 是当前机器人用户名，若不同请替换：

```bash
cd ~/microduck
sha256sum -c microduck-model-suite-20261028.tar.gz.sha256
read -r -p 'Radxa IP: ' ROBOT_IP
scp microduck-model-suite-20261028.tar.gz \
  microduck-model-suite-20261028.tar.gz.sha256 "wmh@$ROBOT_IP:~/"
ssh "wmh@$ROBOT_IP"
```

以下都在 **Radxa SSH 终端**执行。先接住机器人、按 B 卸力、结束已有手动控制，再停服务；没有安装服务则跳过 stop：

```bash
sudo systemctl stop microduck-xbox.service
cd ~
sha256sum -c microduck-model-suite-20261028.tar.gz.sha256
# 首次解压；若目录已有旧内容，先移走旧目录再执行。
test ! -e microduck-model-suite-20261028 && tar -xzf microduck-model-suite-20261028.tar.gz
cd ~/microduck-model-suite-20261028
python3 install.py --target ~/deploy_hd1910
```

最后一条只是预览，使用现有 `.venv/bin/python` 校验代码、14 关节/IMU 标定、HOME 单圈范围、六模型哈希和 **768 条 CPU 推理样本**，不打开硬件。依赖缺失时：

```bash
~/deploy_hd1910/.venv/bin/python -m pip install -r payload/requirements.txt
python3 install.py --target ~/deploy_hd1910
```

预览通过，再执行安装：

```bash
python3 install.py --target ~/deploy_hd1910 --apply
cd ~/deploy_hd1910
.venv/bin/python scripts/model_suite.py check --config robot.json
```

安装器保留 `robot.json`、用户舵机映射和 `/etc/default/microduck-xbox`；不启动服务或运动。被更新文件先备份到 `backups/model_suite_20261028_*/`，复制或安装后验证失败会回滚。已有标定不合格或控制进程仍占用设备时会拒绝。

## 4. 选择模型并用 Xbox 运行

**Radxa**，先预览默认选择：旧行走保持、重心坐站、俯身啄取、滚翻关闭。

```bash
cd ~/deploy_hd1910
.venv/bin/python scripts/model_suite.py select --config robot.json
# 保存选择，但不运动
.venv/bin/python scripts/model_suite.py select --config robot.json --apply
# 启动按键等待流程，策略运行 10 秒；需后续 A / Menu 才运动
.venv/bin/python scripts/model_suite.py run --seconds 10 --max-vx 0.2
```

每次 `run` 都按本次参数重新选择，省略参数即采用上述默认值。分别试新行走或开启滚翻：

```bash
# 新行走：仍有低速、后退、侧移、转向响应不足
.venv/bin/python scripts/model_suite.py run --walking new --seconds 10 --max-vx 0.2
# 原行走 + 重心坐站 + 显式启用实验滚翻
.venv/bin/python scripts/model_suite.py run --roulade on --seconds 10 --max-vx 0.2
```

坐站对照可传 `--sitstand original` 或 `--sitstand friction`。`--walking keep` 意为保留**当前** `robot.json` 中的行走模型，不会恢复之前的模型；切换前应保留配置备份。试过 1849 后，要恢复本项目此前使用的模型可运行已有入口：

```bash
bash xbox_model_hd1910.sh models/hd1910_backlash_30000.onnx 10 0.2
```

| 操作 | 作用 |
| --- | --- |
| A | 托住机器人、双脚悬空，回到已标定 HOME |
| Menu / ≡ | HOME 就绪后双脚落地、摇杆居中、保持静止；校偏和对齐后开始策略 |
| 左摇杆 / 右摇杆左右 | 前后/侧移速度，转向；具体响应取决于所选模型 |
| Y | 坐下 / 站起 |
| RB | 一次约 4 秒俯身啄取，然后回站立 |
| LB | 仅 `--roulade on` 时：先停步，再前滚翻，检测完成后回站立 |
| X | 嘴动作，需原有嘴部标定 |
| B / 手柄断连 | 停止并卸力，提前接住机器人 |

滚翻期间不排队执行 LB/Y/RB。监测器要求实际翻转、向前累计转动和重新站稳；5 秒未完成、持续反向转动超过 90°、侧翻或异常反馈会停止。这里使用的仿真 IMU 是理想信号，真实 IMU 滤波与冲击仍需首机检查。

本包不改开机自启设置；手动验收后再按主手册第 16 节配置服务。长期运行可显式用 `--seconds 0`，先完成短时验证。
