## 0.2.1 用户舵机编号

- 共 **132 项测试通过，另含 90 项 unittest 子检查**。
- `servo_ids.user.json` 保存用户提供的关节 ID 1–14；不推测方向或编码器零位。
- `map-ids` 只修改本地配置并备份；保留串口、IMU、模型和控制设置。
  编号变化时清除对应关节的方向/零位确认，并令全局标定失效；未变关节保留。
- 验证相同编号重复导入不改文件、不增加备份；批量交换编号不会产生中间状态。
- 缺失/多余关节、重复 ID、布尔值、非整数、越界值在修改前被拒绝，原配置不变。
  CLI 测试确认导入过程不打开舵机总线或 IMU。

## 0.2.0 直腿标定与回 HOME

- 共 **126 项测试通过，另含 80 项 unittest 子检查**。
- 新增 `calibrate --pose straight` 和只读 `home-plan`；确认保存的是实际参考刻度，
  单圈越界/采样移动时不会覆盖已有标定，预览不打开 IMU/ONNX，不发任何电机写入。
- 用当前训练 XML 独立计算直腿参考，角度为 ±58.411873326924°。
  核对 H/K/A 侧投影竖直、足与头参考方向、颈轴竖直及 1001 个插值角度均在模型限位内。
  实际几何及限制见 [几何报告](直腿参考几何核对.json)。没有把角限位检验称为无碰撞证明。
- 使用目标和测量分离的模拟舵机：8秒、400步的过渡单调并到达精确训练 HOME，
  连续目标峰值速度不超过12°/s；编码器量化另按一格误差处理。`home` 不加载/推理 ONNX。
- 核对映射/参考记录损坏、姿态偏离、设置 RAM 增益期间姿态改变、硬件角限位失效/超界会拒绝运动。
- 卡轴、反向响应、反馈跳变在发送下一目标前停止并尝试卸力。
  原有掉线、读回失败、超时、异常退出等测试继续通过。
- 普通 `home/run` 的0.6rad启动范围保留，`run`不接受直腿例外。
- 注入一次35ms串口读取延迟，验证过渡目标发送至少间隔20ms，延迟只延长完成时间，不追赶补发。
- CLI 帮助与 Bash 语法检查通过。

## 尚需在你的机器验证

串口设备、ID 唯一性、HLS_2 寄存器与模式、同步读支持、现有速度/加速度/电流限制、
关节零位和方向、实际机械限位、IMU 型号和安装坐标、Linux 接口权限、50 Hz 周期、供电和温度。
需先完成只读诊断和台架 HOME，再评估短时策略表现。

当前配置保留硬件原有速度/加速度/电流限制。HLS_2 资料与通用 STS 关于零速度值的解释存在差异，
也没有本机 phase 和固件读数，因此本包不把其它机器的 0 值作为通用写入预置。
若 HOME 不跟随，应保留 `logs/servos.json` 与 `.session.json`，进一步核对这些字段。

模式测试和软件看门狗不能证明系统卡死或电缆断开时必能卸力；这依赖独立的断电手段。
