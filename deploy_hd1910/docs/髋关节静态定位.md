# duck1 四髋静态定位

适用：2、3、12、13 号，HD1910 HLS_2 模式 4，已有 HOME 软件标定。

2026-10-31 实测中，P=5/D=0/I=0 时，3 号目标改变 27 刻度而实际仅移动 2 刻度；13 号目标返回 2511 后实际仍在 2536。IMU 前后倾未恢复。后续只读检查显示死区寄存器均为 1 刻度，不能把此次误差直接解释为软件死区。低增益、负载、静摩擦或机构问题仍需通过实际跟随测试区分。

`scripts/hip_position_hold.py` 提供一个受支撑的静态定位候选参数 P=16/D=0/I=0。它不保证任意负载下都能精确到位。P=5 是当前行走策略使用的参数，静态参数不写入 `robot.json`，也不能直接交给策略接管。

## 操作

先关闭其他舵机程序。原 HOME 目标应已生效，14 颗身体舵机应都上力。托稳躯干和头部，让双脚离地；全程承担机器人重量，不依靠正在切换增益的髋关节支撑。

```bash
cd "$HOME/deploy_hd1910"
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1

.venv/bin/python scripts/hip_position_hold.py --move --supported --p 16
```

程序只处理四髋，逐颗短暂卸力、写 RAM 参数、读取并预载当前位置、恢复保持，再以每 100ms 最多 1 刻度回原 HOME。结束时保留上力。验收使用实际反馈，要求误差不超过 6 刻度（约 0.53°），并检查窗口内晃动；不能用“目标已发送”代替“已到位”。四髋以外的身体关节及嘴部不接收写指令。

然后双脚平放水平防滑硬地面，自然承重；使用防倒支撑，允许躯干轻微转动。先只读验收，成功后才调平：

```bash
(
set -e
cd "$HOME/deploy_hd1910"
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1

.venv/bin/python scripts/hip_position_hold.py --seconds 5
.venv/bin/python scripts/level_hip_stance.py \
  --move --ground-supported --tolerance-deg 0.5 --save-home
)
```

只读验收未通过会返回非零状态，后续调平不会启动。提高增益后仍不到位或出现持续晃动，需要检查机械干涉、受力与供电；工具不自动继续加 P，也不改电流上限。

## 恢复行走参数

行走前再次托稳躯干、双脚离地，执行：

```bash
cd "$HOME/deploy_hd1910"
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
.venv/bin/python scripts/hip_position_hold.py --move --supported --p 5
```

切回 P=5 后受载静差可能重新出现。日志会分别记录 RAM 参数是否已恢复、实际位置是否通过静态精度验收；“位置未达标”不等于参数写入失败。不要通过修改策略参数或删除接管检查，让模型直接使用 P=16。

## 停止与记录

每次开始写入前，工具将完整参数和反馈保存到 `logs/hip_position_hold_*.json`。不修改 HOME、软件零位、IMU、模型、EEPROM、工作模式或电流限制。

`Ctrl+C`、`q` 回车或异常会终止正常操作。若已开始切换，程序尝试只恢复已处理髋关节的原 RAM 参数，并在当时实际位置保持；不会发出整机卸力。若某颗无法安全恢复，会尝试仅将该颗卸力并明确打印结果，因此执行和异常处理期间都必须保持支撑。

增益只存在于 RAM；重启后的实际值需要重新读取。正常到位结束保留当前增益与上力。软件测试验证指令边界及故障处理，不代表已经验证新参数的实机跟随效果。
