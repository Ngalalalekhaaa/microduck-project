# 本机 HD-1910 网页调试台

基于 microduck-replica 的 servo-web 0.15.4，版本 0.15.4-hd1910.3。上游提交见 UPSTREAM_COMMIT，原说明保存在 README.upstream.md。

## 当前运行状态

2026-09-30：已按用户要求恢复“全部扭矩开”和单颗扭矩开关。上力保持会先检查完整反馈、单圈范围、模式和硬件限位，再逐颗把目标对齐最新实际位置；写目标可能触发输出，所以将该步骤视为上力的一部分。目标、扭矩和反馈读回通过才报告成功，失败尝试关闭本批新增上力。上力前需支撑躯干。

当前允许读取、保存姿态、上力保持和卸力；滑块目标、姿态回放、HOME及内部校准仍停用。编码器2048仅表示用户选定的近似中位，模型方向/参考角度标定尚未完成。启动服务只读取，不自动上力。

之前14号重标定的收尾曾发现torque=1并立即卸力；随后省略目标写入42，仅发0x0B对14颗重设中位时均保持torque0。恢复的上力代码同时支持“写目标后自动开启”和“需要另写扭矩开关”两种情况；没有通过再次重标定来试验固件行为。

## 在 Radxa 运行

```bash
cd ~/servo_web_hd1910
bash install.sh
bash run.sh
```

浏览器打开 `http://10.128.165.157:8080`（IP 改变时相应修改）。确认页面没有显示“模拟”。串口 /dev/ttyS2 同时只能由一个控制程序使用。Ctrl+C 停止服务。

本版的 3D 库随包提供，页面不用访问外部 CDN。启动仅查询舵机；当前可显式上力保持，位置运动入口停用。

## 保存实际姿态

托住躯干并卸力，摆好参考姿态。在“姿态”栏填写名称，点击“把当前实际位置存成姿态”。保存的是实际读数，不是滑块目标；缺任何一个配置中的舵机读数就拒绝保存。同名多次保存不会覆盖。文件在本目录 `poses/` 中。

作者机器的示例姿态保存在 `examples/upstream-poses/`，不会出现在操作列表。模拟保存的姿态带 fake 标记，不会在真实舵机连接下显示。

## 方向、零位与训练 HOME

默认只读加载 `~/deploy_hd1910/robot.json`，可通过 `--deploy-config /path/to/robot.json` 指定。只有关节名称、ID、direction、zero_tick、mapping_verified 全部匹配，才会作为已验证标定使用；不会自动修改部署配置。网页方向按钮记录在本目录 directions.json；改变为与部署配置不符的方向后，该关节会重新显示未标定。

目前仅完成编号适配，原部署配置的方向、零位仍为空。页面显示未标定，不把 2048 当作已经验证的实物零点；此时 3D 只显示相对于首次读数的变化。训练 HOME、模型零位和其他预设的发送需要 14 个身体关节全部在线并完成软件标定。嘴部不随训练 HOME 运动。原版 EEPROM 一键校准入口已隐藏，真实设备上对应操作被拒绝，避免与部署程序的软件零位混用。原始寄存器写入、改 ID 入口也已停用，保留只读导出。

保存任意姿态不等于标定 HOME。参考姿态应与训练模型和实际结构核对后，再用部署程序建立角度对应关系。本页保存的 JSON 作为实际刻度记录，不会自动覆盖 robot.json。

真机回放采用 20 Hz 位置插值，仅写目标位置，不套用 STS 的速度单位或改写速度、加速度、电流限制。实际到位时间取决于舵机现有设置。坐姿、折叠和灵动尚未在本机核对，真机执行入口暂不开放。
